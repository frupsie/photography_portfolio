## Design Specificity Verdict

Camera/EVF motif is genuinely load-bearing across the whole site (intro HUD, lightbox chrome+EXIF, 404 copy, About's real Workflow) — not a template. But PRODUCT.md's stated organizing spine (chronology, "the journey") isn't actually implemented in the information architecture anywhere, only in copy/vibe.

Deterministic scan: CLI clean. Browser scan found wide-tracking/layout-transition recurring identically on all 5 pages (confirmed false positives), plus page-specific findings: tight-leading (Home), hero-eyebrow-chip (About + Contact, two different class-naming conventions for the same pattern), and a new one: .city-page__count renders at 10.88px, under the 11px floor.

## Overall Impression

Every individual page is well-built and held up under fresh review. What only a whole-site pass catches: two separate "browse by city" systems that never link to each other, chronology claimed as the organizing idea but not implemented on either surface meant to embody it, and a floating back-to-top button that sits on top of the photo lightbox and stays clickable the whole time it's open — none of these exist when testing any single page alone.

## What's Working

- PhotoLightbox is one real shared component (Home, Gallery, City) with identical EXIF/nav/focus handling.
- URL-driven Gallery state is a genuine cross-page win — shareable, bookmarkable, reload-safe.
- Error/empty states share one calm, on-brand voice sitewide.

## Priority Issues

**[P1] Back-to-top button sits on top of the photo lightbox, stays clickable**
.back-to-top is z-index 2100 (comment claims "below modals") while .photo-lightbox is z-index 1000. Verified live: elementFromPoint at the button's position returns the button itself with the lightbox open, pointer-events auto. Breaks aria-modal's own contract. Fix: raise lightbox/nav-drawer/intro above 2100, or disable back-to-top while an aria-modal element is mounted.

**[P1] Two disconnected city-browsing systems, neither chronological**
/city/:slug reachable only from Home's index (one link sitewide); Gallery's city pills never link there. Home hardcodes COUNTRY_ORDER=['Japan','China','South Korea']; Gallery derives China/Japan/South Korea from cities.js's raw order. Neither is chronological. COUNTRY_ORDER is exactly the hand-maintained-second-list anti-pattern CLAUDE.md already documents as a past incident (Kamakura). Fix: derive country order from cities.js by earliest year in one place, reuse everywhere; cross-link City pages and Gallery both ways.

**[P2] Gallery and City pages have no designed ending**
Home has a deliberate closer; Gallery and City pages run straight into the footer. Gallery is the page a skimming visitor is statistically most likely to end on, and it's the one with no closing beat. Fix: give Gallery (and optionally City) a closing acknowledgment consistent with Home's.

**[P2] Root-level page-transition not reduced-motion-gated on 4 of 5 pages**
ContactPage's root transition is reduceMotion-gated; About/City/Gallery/NotFound hardcode their root duration even though About/Gallery/City already gate their inner content. The earlier fix stopped one level short of each page's own wrapper. Fix: extend the same pattern to all root transitions.

**[P3] Four different page-transition treatments, Home has none**
Home: no motion wrapper at all (confirmed in source). Gallery/City: pure fade 0.5s. Contact/NotFound: fade+slide 0.5s. About: asymmetric fade-in/slide-out 0.4s. Fix: pick one shape and duration, or document Home's exception deliberately.

## Persona Red Flags

Casual browser: delighted by intro + Home's index-to-photo panel, but the hero's "See the Gallery" CTA skips Home (and City pages) entirely for anyone who takes it directly; visit has no real end on Gallery.
Skimming client: served well by Gallery filters and About's stats, but landing on a City page first offers no lateral city-to-city comparison and no link back to Gallery's fuller filters.

## Minor Observations

- Navbar's active link uses a CSS class only, never aria-current; Gallery's filter pills use aria-current correctly for the same concept; Footer has no active-state indication at all. Three treatments of one idea.
- Home's primary CTA uses --home-gold/3px offset for focus-visible where every other CTA sitewide uses --accent/2px — plausibly intentional (Home's own token system) but undocumented as such.
- Hover behavior differs in kind across primary CTAs: color-only vs full fill-swap vs opacity dim.
- .city-page__count renders under the 11px floor, the same defect class fixed elsewhere this session.
- hero-eyebrow-chip pattern uses two different class-naming conventions (ap- prefix vs content-page prefix) between About and Contact.

## Questions to Consider

- What if City pages became the canonical browse-by-city surface (with prev/next-city in arrival order), and Gallery's grid became explicitly the "skim everything" alternate view?
- What if Home's closer appeared, reworded, at the bottom of Gallery and City pages too?
- What if country/city order derived from one sorted pass over cities.js instead of three separate hand-authored orders?
